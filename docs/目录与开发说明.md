# 目录与开发说明

首次接手请先读 [开发入口](development/GETTING_STARTED.md) 和 [当前协作状态](collaboration/STATUS.md)。共同开发约定在根目录 `AGENTS.md`；本页补充目录和既有机制。

## 源码和资源

`desktop/` 负责原生 Windows 界面、时间轴和实时预览，`studio/` 负责 GameMaker 工程同步、GML 生成及外部耐久兼容。后台服务使用进程管道通信。

可视资源统一放在 `assets/`：图标在 `icons/`，地形在 `terrain/`，源贴图在 `sprites/`，第三方素材包在 `sprite-packs/`，英文词表在 `locales/en.json`。原始素材包内部的分类和名称保留，便于核对来源。

`templates/avoidance.gm82/` 是新建工程模板。`projects/` 是实际编辑的工程；不要将个人耐久、歌曲、存档和底片混进应用资源中。

随机参数由 `desktop/RandomParameters.cs` 与 `studio/random-parameters.mjs` 使用相同的表达式语法和种子算法；右栏操作在 `RandomParameterUI.cs`。固定随机参数取样一次；含时间、坐标等上下文的公式按其规则计算。Beta 还区分每颗、每轮与整组的出生取样，以及弹幕年龄行为。预览与 GML 使用独立随机状态，避免改写原生耐久的随机数发生器。表达式和关键帧的取样标识会随复制、预设和工程一起保存。

时间轴中的 `Track` 数据仍表示一个物件，新增 `lane` 表示它所属的编号轨道。`TimelineLayout.cs` 处理旧工程迁移与重叠错层，`TimelineCanvas.cs` 为每个物件保存独立展开状态。可用 `desktop/Test-RandomTimeline.ps1` 检查跨语言取样及原生控件交互；该脚本不会启动游戏。

## 本地构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File desktop/Build-Native.ps1
```

生成 `build/RufMaker.native.exe`。构建会从 `assets/icons/icon.ico` 读取图标，将图标和英文词表嵌入 EXE。修改图标原图后，可运行 `desktop/Convert-Icon.ps1` 重新生成 ICO。

语言选择保存在 `user-data/settings.json`，与工程分开。中文原文与英文显示在呈现层对应，预设键名、选择项原值、用户名称和 GML 不做翻译或重写。新增界面文案时，在 `assets/locales/en.json` 补充对应英文。

## 引擎准备与首次启动

`desktop/EngineSetup.cs` 负责 GM8.2 检测、官网便携包下载、压缩包导入和运行库检查，`EngineSetupForm.cs` 提供原生配置窗口。所选引擎路径和是否跳过首次提示保存在 `user-data/settings.json`，与语言设置共用该文件。下载后的引擎位于 `GameMaker8.2/`，旧安装备份及临时文件位于 `build/engine-setup/`，这些都不进入 Git 或更新包。

`studio/engine-path.mjs` 为后台服务和命令行工具解析引擎位置。桌面程序将界面中选定的位置传给后台；改选后会重建后台连接，当前工程和编辑状态继续保留。

Release ZIP 不含演示工程。`studio/project-files.mjs` 在没有指定工程、也没有默认工程时，从 `templates/avoidance.gm82/` 创建一个 50 FPS 的空白时间轴工程，将相对路径记在 `user-data/startup-project.json`，后续启动复用。创建与编辑工程不要求安装 GM8.2，编译或生成原生底片时才需要引擎。

本地配置检查：`desktop/Test-EngineSetup.ps1`。增加 `-Online` 可在隔离目录验证官网实际下载和解压；该检查不运行 GameMaker，也不修改现有安装。

## 更新包兼容

发布时同时生成 `RufMaker-版本号-Windows-Portable.zip` 完整便携版，以及旧版自动更新器使用的 `RufMaker-版本号.zip`，分别附 SHA256。完整便携版使用整理后的 `assets/` 目录，包含 EXE、运行文件、模板、素材和使用文档；更新包只替换应用文件。GitHub Actions 在推送版本标签或手动执行时发布，Release 附件标明首次下载的完整软件本体。

`desktop/Test-Updater.ps1` 使用隔离目录和无窗口测试程序，检查版本提示、双方版本号、更新辅助程序退出等待、文件替换、资料保留、备份与重启。发布后加 `-Online` 可使用应用自己的 HTTP 客户端验证 GitHub 最新版本、下载、SHA256 和逐文件校验。

1.6 及更早版本的更新器只接受原来的资源路径。因此 `Package-Release.ps1` 将部分资源以旧路径装入更新包，以便旧安装可以直接更新。

新 EXE 启动时将这些已分发资源整理到 `assets/`。此处理只涉及图标和随附素材，不移动用户工程、歌曲、存档或自定义预设。完整仓库本身直接使用新目录。

演示工程编译的游戏现在输出到 `build/demo/`。早期留在根目录的本机游戏产物归档在 `build/legacy-demo/`，参考视频归档在 `references/videos/`；这些不进入 Git 或更新包。
