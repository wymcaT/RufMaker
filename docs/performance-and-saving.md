# 性能与保存

以下说明适用于 RufMaker 2.6.0，包含此前2.5.0的保存、预览与撤销优化。

## 游戏内音乐校时（本地后续修复，尚未发布）

游戏以逻辑时间轴为准，每约0.1秒检查BGM位置。偏差不超过3帧时不处理；超过3帧时以最多±3%的播放速率修正，回到1帧以内恢复正常速度。50 FPS下，3帧约60ms。速率调整使用引擎的pitch接口，会伴随轻微音高变化。

偏差超过8帧（50 FPS下约160ms）时，直接把BGM定位到逻辑时间；两次定位至少间隔500ms，避免流式音频频繁跳音。不通过跳过弹幕逻辑来追音乐。音乐暂停、停止或歌曲已经结束时不会强行播放或定位。

普通F5的历史准备完成后才开始校时，R恢复会清掉旧的校正速率。普通导出也执行相同规则。原生导入工程若已在耐久控制器的Step事件内校时，则保留原实现；没有校时且能识别FMOD通道和逻辑时钟的，加入独立同步对象。未识别的音频系统/时钟继续由原工程负责。底片录制不执行新增校时。

更新后请保存并重启RufMaker，重新F5或导出；此前已经生成的游戏EXE不会自动改变。编辑器预览原先已按墙钟播放并在约90ms偏差时定位，此次没有修改编辑器的播放倍速或弹幕计算。

## F5 与 R（2.6.0）

F5 会显示同步/编译、运行器启动和历史重算进度，准备期间可以取消。音乐在到达测试点后再定位并播放，避免重算期间歌曲先向前走。

首次到达 F5 选定的测试点时，会保存完整游戏状态。之后按 R 直接恢复这份快照，包含玩家、已生成弹幕、模板、全局变量和已随机出的参数，不会重新创建控制器或从头计算时间轴。切换测试点、修改工程后重新按 F5，会建立新的测试快照。这个行为仅在 F5 试玩中启用，导出游戏仍使用原引擎的 R 存档逻辑。

固定种子模式会沿用测试点的随机状态；随机模式保留测试点已有弹幕的随机结果，只为后续计算更新随机种子。此前的全局变量及静态随机绑定不会重新初始化。原生导入的试玩继续使用游戏内快照恢复。

快速死亡后按R也会回收bloodEmitter持有的粒子系统和粒子类型；恢复请求挂起时不再创建新的死亡特效，避免快照移除对象后仍有血粒子持续喷发。普通场景的装饰粒子不受这项清理影响。修改后需重新F5生成试玩。

F5 首次历史重建可以跳过到目标帧前已经确定销毁的末端弹幕；分裂、生成后代、组复制、运动重设及镜头寿命等依赖需要保留时仍执行原有历史。复制对象共享同源、同一时钟和父模板上下文的当帧形状采样，减少重复求点；关闭拖影时不再保存无用的逐帧拖影历史。数量关键帧与表达式仍保留完整成员容量，以支持缓动超调。

隔离测量中，1800颗复制成员的60帧计算从约7.16秒降到约3.97秒，数量、位置和外观一致。当前工程第1899帧的已编译 F5 从约12.3秒降到约8.7秒；这是该场景的测量，包含约6秒的运行器加载，首次编译另计。R快照恢复不再执行这段加载和历史重算。详细验证见[实施记录](development/PLAY-COPY-PERFORMANCE-2026-10-29.md)。

## 预览与编辑

拖动游标或修改参数后，后台会取消已经过时的预览请求，只有当前场景、当前帧的结果才会显示；对象统计也随同一帧更新。

改名称可以复用弹幕模拟历史。修改后段的关键帧时，会保留不受影响的早期状态，从受影响的插值区段重新计算。随机种子、玩家轨迹、模板定义等会影响历史的修改仍然需要完整重算。镜头在参与“出视野销毁”判断时也会影响模拟。

首次跳到复杂耐久的后段仍需要计算此前历史。检查点最多保留 48 份，估算预算为 32 MiB，兼顾早期和近期位置，改善反向定位。它们只是内存缓存，关闭后会释放。

简化预览现在会绘制全部有效弹幕，取消了原先静默跳过 20000 颗之后弹幕的限制。密集画面因此可能花更多时间绘制，但预览与数量统计会保持一致。原先 200 个物件/轨道的限制也已取消；生成规则自身的数量范围仍然有效。

## 撤销内存

在“工具 → 撤销内存预算”选择 32、64、128 或 256 MiB，默认 128 MiB。撤销与重做共用预算，超出后移除最早的记录。单步特别大时仍保留最近的一步。

这是撤销快照的估算预算，不是整个软件的内存上限。画面、贴图、音乐、底片与模拟缓存另占内存。选项随界面布局保存，跨工程使用。

## 保存与错误恢复

保存先检查资源并生成待写入内容，再提交 GameMaker 资源和 RufMaker 工程数据。歌曲不存在等准备阶段错误不会先改写一半脚本；提交中途失败会尝试恢复提交前的文件。

如果保存进程中断，下次读取工程时会检查工程内的 `.rufmaker-sync` 恢复记录。正常完成后该目录会自动移除。若提示回滚尚未完成，请保留它并重新打开工程；不要把它当缓存手动清理。此机制用于一次保存的一致性恢复，不代替历史版本备份。

预览绘制失败会显示在状态栏，详细信息写到程序目录的 `user-data/logs/preview.log`。连续相同错误只报告一次，修复后可以继续预览。

## 本轮验证范围

已核对失败保存、进程中断恢复、201/1000 物件保存重开、超过 200 的轨道拖动、48000 颗预览及过时请求丢弃。GameMaker 实测包括 1000 个物件启动与绘图，以及实时玩家坐标下 61 帧、1502 条弹幕状态对照。

外部 Verse3 工程已在隔离副本中通过导入、原生代码保留、叠加物件保存重开和 GameMaker 编译；本轮没有重新录制整段底片或完整试玩。合成测试中的耗时不代表每个耐久工程都能达到同样帧率。
